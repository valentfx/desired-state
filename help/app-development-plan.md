## 2026-10-01 — O2Ring live decoding and session recording

- Hardware evidence: the supplied Samsung log contains 15 complete legacy response frames, all CRC-valid, split into 20-byte plus 1-byte BLE notifications. Layout is 55 00 FF 00 00 0D 00 + 13-byte payload + CRC. SpO2 byte 7 was 98, pulse byte 8 was 64–71, battery byte 14 was 61. These mappings match ecostech/viatom-ble; display comparison, off-finger behavior and extended overnight testing are pending.
- Added bounded fragmentation/reassembly, stale-fragment reset and header/length/complement/CRC validation. Decode only this observed live-response layout. Off-finger and zero/sentinel vital values remain null; original frame bytes are always retained. Motion, PI and worn-state bytes retain raw representations; PI scaling is unverified. Once valid legacy responses arrive, OxyII probing stops.
- SessionController now owns O2Ring service/subscriptions above navigation. Closing Diagnostics leaves acquisition running. Start supports H10 with ring, or ring alone. Same-ring automatic recovery retries disconnected/stale streams at 15-second intervals while recording; manual ring disconnect suppresses recovery. Primary H10 RR/HR processing remains unchanged.

Rows carry session/user/device identity, UTC receipt time, timestamp provenance, decoder version, decoded values/availability, CRC-valid assembled frame and complete original TX/RX fragments.
